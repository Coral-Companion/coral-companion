# AGENTS.md

Guidance for AI coding agents (and humans) working in this repository.
Component-specific rules live in nested `AGENTS.md` files; the closest one to the file you are editing takes precedence.

## What this is

Coral Companion is an open-source computer-vision platform for coral restoration monitoring.
Practitioners upload underwater photos; the system segments coral colonies, matches them to previously observed colonies, and supports measurement and comparison over time.

Core flow: **upload image → segment colonies → identify/match against earlier observations → confirm → measure & compare across surveys**.

Domain vocabulary (use these terms consistently in code, UI and commits):
- **Survey** – one monitoring visit/campaign (formerly "monitoring session"; do not reintroduce the old name).
- **Observation** – one coral colony captured in one survey.
- **Colony** – the physical coral tracked across observations.

## Commands

Python uses one conda env for both backend services (`backend/environment.yaml`, env name `coral-companion`).

```bash
# Backend setup
cd backend && conda env create -f environment.yaml && conda activate coral-companion
pip install -r core/requirements.txt
pip install -r segmentation-worker/requirements.txt   # only if working on segmentation

# Backend core: run & test
cd backend/core
uvicorn app.api.main:app --reload --port 8000 --app-dir . --log-level debug
pytest                                   # runs backend/core/test/
pytest app/embedding                     # co-located embedding tests (not in default testpaths)

# Frontend
cd frontend
npm install
npm run dev                              # http://localhost:5173
npm run type-check
npm run build

# api-router
cd api-router && npm ci && npx wrangler dev
```

There is no linter/formatter config committed yet (planned: ruff). Until then, match the surrounding style; VS Code is set up to format Python with ruff and organize imports on save.

## Before you call a change done

- Backend core change → `pytest` in `backend/core` passes.
- Frontend change → `npm run type-check` and `npm run build` in `frontend` pass.
- DB model change → an Alembic migration is included (see `backend/core/AGENTS.md`).
- Renamed a domain concept or endpoint → updated across backend, frontend types/services and docs.
- If you could not run a check (e.g. no DB or GPU available), say so explicitly.

## Boundaries

- **Never commit secrets** or `.env` files. Config is injected via env vars; deployment variables/secrets are defined in `api-router/wrangler.jsonc` / `wrangler secret`. See [backend/README.md](backend/README.md) for the full list.
- **Do not modify `backend/segmentation-worker/third_party/`** (vendored CoralSCOP, CC BY-NC-SA 4.0) beyond minimal integration changes, and keep its LICENSE/NOTICE intact.
- **Do not hand-edit `backend/core/dev_fixtures/`**; fixtures are generated by the segmentation provider (`PRODUCE_FIXTURES=True`).
- **Do not edit or delete existing Alembic migrations** in `backend/core/migrations/versions/`; add new ones.
- Do not touch `.github/workflows/` or `api-router/wrangler.jsonc` deployment settings unless the task is explicitly about deployment. Pushing to `main` deploys.
- No local DB/storage is provided: the backend needs a Supabase Postgres (`DATABASE_URL`) and R2 bucket. Don't run migrations or scripts against a database without being asked.
- Segmentation needs a GPU. For local work without one, use `SEGMENTATION_PROVIDER=fixture` (serves pre-segmented results from `dev_fixtures/`).

## Conventions

- Commit messages: short, imperative, lowercase, optionally prefixed with a [gitmoji](https://gitmoji.dev) (`✨` feature, `🐛` fix, `🧹` cleanup, `🚚` move/rename, `🖊️` docs, `🚀` deploy).
- Keep changes focused; don't mix refactors with feature work.
- Prefer updating the existing component README over adding new docs files.
